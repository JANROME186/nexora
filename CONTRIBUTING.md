# Contributing to Nexora

Todo cambio debe iniciar con una intención clara: negocio, producto, arquitectura, contrato, datos, seguridad, QA o documentación.

## Flujo recomendado

1. Crear rama desde `develop`.
2. Actualizar o crear RFC si el cambio es relevante.
3. Actualizar artefactos de fuente de verdad.
4. Actualizar Knowledge Index si se agregan nodos trazables.
5. Actualizar CHANGELOG.
6. Crear Pull Request.
7. Validar con quality gates documentales.

## Ramas sugeridas

- `main`: versión aprobada.
- `develop`: integración de especificación.
- `spec/*`: cambios de especificación.
- `adr/*`: decisiones arquitectónicas.
- `rfc/*`: propuestas.
- `docs/*`: documentación.
